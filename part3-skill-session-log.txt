SKILL OVERVIEW
--------------------------------------------------------------------------------
The /add-feature skill defines a reusable end-to-end workflow for adding
features to the NeighborSwap project. It enforces architecture conventions,
ensures tests and type-safety, and produces a structured summary on every run.

--------------------------------------------------------------------------------
V1 — INITIAL SKILL (Steps 1–7)
--------------------------------------------------------------------------------
The original skill defined 7 ordered steps:

  Step 1 — Understand the feature
    Re-read CLAUDE.md and PRD.md. State what will be built in one sentence.

  Step 2 — Locate affected files
    Glob/Grep existing files. Read every file before modifying it.

  Step 3 — Plan (no code yet)
    List new files, modified files, DB migrations, new env vars.

  Step 4 — Implement
    Follow CLAUDE.md conventions: functional components, lucide-react icons,
    Server Actions for all mutations, server-only Supabase client, strict TS.

  Step 5 — Write tests
    Co-located Vitest tests. Mock groq-client.ts. Never make live API calls.
    LLM-as-judge eval tests for any AI agent work.

  Step 6 — Type-check and lint
    npx tsc --noEmit && npm run lint
    Fix all errors; no @ts-ignore or as any.

  Step 7 — Summarize
    File diff summary, manual test steps, test results, outstanding TODOs.

Constraints: no RLS bypass, no fetch('/api/...') for mutations, no direct
Groq SDK imports in agents, no speculative features beyond the request.

V1 → V2 ITERATION — What changed and why
--------------------------------------------------------------------------------
USER FEEDBACK:
  "Please update the skill — add a process to avoid the 'next.config.js
   missing / npm run lint can't run' problem. If there is a pre-existing
   gap or bug, please try to solve the gap or fix the bug and ask me to
   verify."

CHANGE MADE — Added Step 0 "Health-check the codebase":

  Before any feature code is written, run all quality gates:
    npx tsc --noEmit
    npm run test
    npm run lint

  For each failure unrelated to the new feature:
    1. Diagnose the root cause.
    2. Fix it (no @ts-ignore / eslint-disable / as any).
    3. Re-run to confirm the fix.
    4. Ask the user to verify before proceeding:
       "I found and fixed a pre-existing issue: <description>.
        Please confirm this looks correct before I continue."

  Exception: large-scope failures (missing external service, broken DB
  migration) are documented in the final summary instead of blocking the run.

ALSO FIXED (as Step 0 would have caught):
  - Installed eslint + eslint-config-next
  - Created eslint.config.mjs (ESLint 9 flat config)
  - Updated package.json: "lint": "next lint" → "lint": "eslint src"
  - Confirmed npm run lint now passes

VERSION BUMP: frontmatter version: 1 → version: 2
CHANGELOG: added to top of skill file documenting what changed and why
